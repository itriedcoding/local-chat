Overview

Local Chat is a desktop chat client that runs language models on your own computer. It supports three backends:

  • llama.cpp (bundled through node-llama-cpp) — load a .gguf file directly and chat with it offline.
  • Ollama (optional) — connect to a local Ollama server and use any model you have pulled.
  • LM Studio (optional) — connect to LM Studio's local server and use any model loaded there.

The interface has five tabs: Chat, Editor, Models, Discover, and Settings.

Installation

Local Chat ships as a 64-bit Windows application. You can use the installer or the portable build — both are on the downloads page.

Installer

  1. Download Local-Chat-Setup-2.1.0.exe and run it.
  2. The installer is per-user and does not require administrator rights. Choose a folder if you like, then finish.
  3. Launch Local Chat from the Start menu shortcut.

Portable

The portable build is a single .exe with no installation step. Put it anywhere and run it directly — handy for a USB stick or a locked-down machine.

First launch: no model is loaded yet. Local Chat will tell you to add one. Head to the next section.

Getting models

There are four ways to get a model into Local Chat.

1. Download from Hugging Face (in-app)

Open the Discover tab, search, and download. Files are saved to Local Chat's own models folder and registered automatically. See Downloading from Hugging Face.

2. Add a GGUF file you already have

On the Models tab, click + ADD GGUF FILE and pick a .gguf file anywhere on disk. Local Chat records its path and makes it available in the model selector. Use REVEAL to open a model's folder and DELETE FILE to remove the file itself.

3. Use an Ollama model

If you already have Ollama running, its models appear on the Models tab under OLLAMA. See Using Ollama.

4. Use an LM Studio model

If LM Studio's local server is running, its loaded models appear on the Models tab under LM STUDIO. See Using LM Studio.

Choosing a model

GGUF models are quantised to trade quality for size. As a rough guide:

  • Q4_K_M — the usual sweet spot for quality versus memory.
  • Q5_K_M / Q6_K — better quality, larger files.
  • Q8_0 — near-lossless, heavy.

Memory needed is roughly the file size plus the context buffer. A 7–8B model at Q4_K_M is around 4–5 GB.

Downloading from Hugging Face

  1. Go to Discover.
  2. Type a query such as llama 3.1 instruct gguf or qwen2.5 and press SEARCH. Results are sorted by downloads.
  3. Pick a repository; Local Chat lists its files and marks which ones are .gguf.
  4. Click a file to download it. A progress bar shows percentage and speed, and you can CANCEL at any time.
  5. When it finishes, the model is added to your library and selectable from the sidebar.
This is the only time Local Chat uses the internet on its own behalf: it calls the Hugging Face API to list models and files, and their CDN to download the file you chose. Nothing about your chats is sent.

Using Ollama

Local Chat can drive an Ollama server running on your machine. Install Ollama from ollama.com, then pull a model, for example:

ollama pull llama3.1
  • In Local Chat, open Models and click ↻ REFRESH OLLAMA. Your pulled models appear under the Ollama section.
  • Ollama runs at http://127.0.0.1:11434 by default. Change it under Settings → Ollama server URL if you run it on another port or host.
  • Ollama models are prefixed and tagged ollama in the model list.

Generation settings (temperature, top-p, top-k, repeat penalty, max tokens, system prompt) are passed through to Ollama for the request. Context size, threads and GPU layers are managed by Ollama itself.

Using LM Studio

Local Chat can also drive an LM Studio server. Install LM Studio, load a model, then start its local server from the Developer tab.

  • In Local Chat, open Models and click ↻ REFRESH LM STUDIO. Your loaded models appear under the LM Studio section.
  • LM Studio serves an OpenAI-compatible API at http://127.0.0.1:1234 by default. Change it under Settings → LM Studio server URL if you run it on another port or host.
  • LM Studio models are prefixed and tagged lm studio in the model list.

Generation settings (temperature, top-p, max tokens, system prompt and so on) are passed through to LM Studio for the request. Context size, threads and GPU layers are managed by LM Studio itself.

Chatting

  • Select a model in the ACTIVE MODEL dropdown in the sidebar. Its state shows as loaded, loading, or not loaded.
  • Type in the composer and press Enter to send, Shift+Enter for a newline.
  • Responses stream token by token. While generating, a STOP button appears.
  • A tok/s figure appears on each reply so you can gauge performance.
  • Use ↻ REGEN in the chat toolbar to regenerate the last assistant reply.
  • Hover a message and use copy to put its text on the clipboard.
  • + NEW CHAT starts a fresh conversation; all conversations are listed in the sidebar and stored locally.

Code editor

Local Chat ships with a built-in code editor so you can build projects, apps, websites and scripts without leaving the app. It works with any text-based language.

  1. Open the Editor tab.
  2. Click OPEN FOLDER and choose a project directory. The file tree appears on the left.
  3. Click a file to open it. Syntax highlighting is chosen automatically from the file extension.
  4. Edit, then press Ctrl+S (or the SAVE button) to write the file to disk.

Toolbar

  • OPEN FOLDER — choose the project directory.
  • + FILE / + FOLDER — create an entry in the current folder.
  • SAVE — write the open file (also Ctrl+S).
  • RENAME / DELETE — act on the open file; deleting sends it to the Recycle Bin.
  • REVEAL — show the file in Windows Explorer.

Editing and shortcuts

  • Ctrl+F find, Ctrl+H replace, Ctrl+/ toggle comment.
  • Brackets auto-close and matching brackets are highlighted.
  • Right-click a file or folder in the tree for New, Rename, Delete and Reveal.
  • Common heavy folders such as node_modules and .git are hidden from the tree for speed.

Viewing archives

Click a .zip in the file tree to list its contents, with entry names and sizes, without unpacking it. Use EXTRACT in the toolbar, or right-click the archive and choose Extract here, to unpack it into a new folder beside the archive.

All file operations are scoped to the folder you opened, so the editor only touches files inside your project.

Attaching files

You can give the model extra context by attaching files to a message. Click the 📎 button in the composer, or drag files onto the chat.

  • Text and code files are read and included in the prompt so the model can see their contents.
  • Archives such as .zip are listed entry by entry (names and sizes).
  • Other binary files (for example .exe) are attached by name and size; their bytes are not sent to the model.
  • Audio and video files are declined — they are not supported.
Attachments stay on your device. Their contents are only placed into the prompt for the generation you send, and large text is trimmed to keep within the model's context window.

Settings reference

Open the Settings tab. Values are saved to disk and applied to new generations.

  • System prompt — the instruction prepended to every conversation.
  • Temperature — randomness. Higher is more creative (default 0.7).
  • Top P — nucleus sampling cutoff (default 0.95).
  • Top K — how many top tokens to consider (default 40).
  • Repeat penalty — discourages repetition (default 1.1).
  • Max tokens — maximum length of a reply (default 1024).
  • Context size — total tokens the model can attend to: 2048, 4096, 8192, 16384 or 32768. Larger contexts use more memory.
  • Threads — CPU threads for local inference. 0 means automatic.
  • GPU layers — how many layers to offload to the GPU. 0 keeps everything on the CPU.
  • Ollama server URL — where to find your Ollama server.
  • LM Studio server URL — where to find your LM Studio server.
Changing context size, threads or GPU layers reloads the local model, because those are set when a model is loaded into memory.

RESET restores the defaults above. The DANGER ZONE section can delete every stored conversation.

Exporting chats

Use the chat toolbar to export the current conversation:

  • ↓ MD — a Markdown transcript with your turns and the assistant's turns.
  • ↓ JSON — the full conversation object, including model name and metadata.

A save dialog lets you choose where to write the file.

Your data

Local Chat keeps everything under your Windows user data directory, in a folder named Local Chat:

%APPDATA%\Local Chat\
├─ settings.json   # your generation + runtime settings
├─ models.json     # the models you added
├─ chats.json      # your conversations (most recent 300)
└─ models\         # GGUF files downloaded in-app

There is no account and no cloud sync. See the privacy policy for the full picture.

Build from source

Local Chat is an Electron app. With Node.js and npm installed:

# install dependencies
npm install

# run in development
npm start

# build the Windows installer + portable exe
npm run dist

Artifacts are written to the dist\ folder.

Troubleshooting

The model selector is empty

Add a model first: download one from Discover, add a local .gguf, or refresh Ollama.

Generation is very slow

Local speed depends on your hardware and model size. Try a smaller model or a lower quantisation, raise the thread count, or offload layers to the GPU if you have one. Close other memory-heavy apps.

"Could not reach Ollama"

Make sure Ollama is running and that the URL in Settings matches. Confirm with ollama list in a terminal.

"Could not reach LM Studio"

Start the local server in LM Studio (Developer tab) and make sure the URL in Settings matches, usually http://127.0.0.1:1234.

A download fails or stalls

Cancel it and retry — large files over a slow connection can time out. Check that you have free disk space.

Where do downloaded models go?

Into %APPDATA%\Local Chat\models\. Use REVEAL on a model to open that folder.
